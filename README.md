# Онлайн-тест для учеников

Готовое веб-приложение: ученик открывает ссылку, вводит ФИО, проходит
случайные вопросы из вашей базы с таймером, красивыми анимациями и защитой
от повторного прохождения. Учитель получает результаты в Google Таблице.

## Структура файлов

```
quiz/
├── index.html          — страница теста
├── app.js              — логика теста
├── config.js           — настройки (сюда вставляете свою ссылку Apps Script)
├── apps_script.gs       — код для Google Apps Script (приём результатов)
├── convert_csv_to_json.py — конвертер вопросов из таблицы в формат теста
└── data/
    └── questions.json   — БАЗА ВОПРОСОВ (редактируете вы)
```

## Шаг 1. Загрузить на GitHub Pages

1. Зайдите на github.com под своим аккаунтом, создайте новый репозиторий
   (например `test-online`), сделайте его **Public**.
2. Загрузите туда все файлы из этой папки (кнопка "Add file" -> "Upload files",
   либо через git).
3. Перейдите в Settings -> Pages, в разделе "Source" выберите ветку `main`
   и папку `/ (root)`, сохраните.
4. Через 1-2 минуты ваш тест будет доступен по адресу:
   `https://ВАШ_ЛОГИН.github.io/test-online/`

Эту ссылку и отправляйте ученикам.

## Шаг 2. Подключить сохранение результатов (Google Sheets)

1. Создайте новую Google Таблицу: sheets.google.com -> "Создать".
2. Откройте меню **Расширения -> Apps Script**.
3. Удалите весь код-заготовку и вставьте содержимое файла `apps_script.gs`.
4. Нажмите "Сохранить", затем **Развернуть -> Новое развертывание**.
   - Тип: **Веб-приложение**
   - "У кого есть доступ": **Все (Anyone)**
5. Нажмите "Развернуть", разрешите доступ (потребуется подтвердить через ваш
   Google-аккаунт — это нормально, скрипт работает только в вашей таблице).
6. Скопируйте URL веб-приложения (вид `https://script.google.com/macros/s/.../exec`).
7. Откройте файл `config.js` в репозитории и вставьте этот URL в строку:
   ```js
   SCRIPT_URL: "ВАШ_URL_ЗДЕСЬ"
   ```
8. Сохраните и закоммитьте изменение.

Теперь после каждого прохождения теста в вашей Google Таблице на листе
"Результаты" появится строка: имя ученика, правильных/из, процент, время
выполнения, дата.

Чтобы посмотреть результаты — просто откройте свою Google Таблицу.

## Шаг 3. Пополнение базы вопросов

Самый простой способ — вести вопросы в отдельной Google Таблице со столбцами:

```
question | answer1 | answer2 | answer3 | answer4 | correct
```

где `correct` — номер правильного варианта (1-4).

Когда хотите обновить тест:
1. Скачайте таблицу как CSV (Файл -> Скачать -> CSV).
2. Запустите:
   ```
   python convert_csv_to_json.py questions.csv data/questions.json
   ```
3. Загрузите обновлённый `data/questions.json` на GitHub (можно прямо через
   веб-интерфейс GitHub: открыть файл -> карандаш "Edit" -> вставить новое
   содержимое -> Commit).

Изменения появятся на странице теста сразу после обновления страницы.

### Формат questions.json (если редактируете вручную)

```json
[
  {
    "id": 1,
    "question": "Текст вопроса?",
    "answers": ["Вариант 1", "Вариант 2", "Вариант 3", "Вариант 4"],
    "correct": 1
  }
]
```

`correct` — индекс правильного ответа в массиве `answers`, **считая с 0**
(0 = первый вариант, 1 = второй и т.д.).

## Настройки теста

В файле `config.js`:

- `TIME_LIMIT_MINUTES` — время на тест (по умолчанию 30 минут).
- `DEFAULT_QUESTION_COUNT` — сколько вопросов выбирается при опции "30".
- `TEST_TITLE`, `TEST_SUBTITLE` — заголовок и подзаголовок на странице.

Ученик сам выбирает на старте: пройти 30 случайных вопросов или все вопросы
из базы. Вопросы и варианты ответов перемешиваются каждый раз случайным
образом.

## Защита от повторного прохождения

Реализована через `localStorage` браузера: если ученик уже ввёл своё ФИО и
прошёл тест на этом устройстве/браузере, повторно с тем же именем пройти не
получится (даже если откроет ссылку снова). Это базовая защита — если
ученику принципиально нужно дать вторую попытку, можно очистить данные сайта
в браузере (или открыть в режиме инкогнито).

Для более строгой защиты (на уровне сервера, по всем устройствам) можно
дополнительно проверять в Apps Script, есть ли уже такое имя в таблице
результатов, и возвращать ошибку — но это требует синхронного запроса с
CORS, что усложняет настройку. Текущий вариант покрывает большинство
реальных случаев (списывание/повторное прохождение с того же устройства).
